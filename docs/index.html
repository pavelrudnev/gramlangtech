Recap

We’ve learnt about the hierarchical organisation of natural-language expressions

  • words
    • consisting of morphemes, organised by dedicated morpheme-ordering rules
  • phrases
    • consisting of words, organised by dedicated word-ordering rules
  • sentences
    • consisting of phrases (and/or other sentences), organised by dedicated rules

We’ve also established that we humans possess cognitive biases favouring the acquisition of hierarchical structure-sensitive rules.

  • Operations
  • Edit distance
  • insertion: insert a letter
    • aquire → acquire
  • deletion: delete a letter
    • arguement → argument
  • substitution: replace one letter with another
    • calandar → calendar
  • transposition: swap the position of two adjacent letters
    • concsious → conscious
  • definition
  • illustration

minimum number of operations that it takes to transform one string into the other

  • quantify the steps to turn a misspelled word into the correctly spelled target word,
  • or inversely to quantify how the target word can be turned into the misspelling

edit distance between Catherine and Kathryn is 4:

  1. replace C with K: [Katherine]
  2. delete first e: [Kathrine]
  3. delete second e: [Kathrin]
  4. replace i with y: [Kathryn]

Non-word errors: upshot

  • most non-word errors can easily be fixed by referring to a dictionary;
  • potential difficulties with segmentation.

Local syntactic errors

Can never be fixed by reference to dictionary.

(1)

*Their was a problem yesterday.

  • possessive their takes the place of locative there
    • both are pronounced the same way in all English varieties
  • both their and there are actual English words that can will be found in every dictionary
  • source of error is grammar

Long-distance syntactic errors

These involve syntactic violations spread out over many more words than one.

(2)

The key to the cabinets are on the counter.

The error above is known as agreement attraction

  • be ought to agree with the key to the cabinets (key is the head of the NP [NP key [PP to the cabinets]])
  • instead, be agrees with cabinets

Semantic errors

These are errors with meaning; we’ll set them aside for now.

Spell-checkers

A simple spell-checker

  • detects errors
    • by reference to a dictionary,
      • which requires a list of words and their uninflected forms;
  • generates candidate corrections;
    • compute candidates with edit_distance = 1
  • ranks candidate corrections to choose the best one.

Lemmatisation

removing inflectional morphology to return a word’s ‘basic’ form

import spacy
sp = spacy.load('en_core_web_sm')
for token in ['compute', 'computed', 'computing', 'computer', 'computers']:
    print(token + ' --> ' + sp(token)[0].lemma_)
compute --> compute
computed --> compute
computing --> computing
computer --> computer
computers --> computer

Note that computer does not lemmatise to compute, and nor does computing.

  • compute, computer, computing are all different lexemes
  • spaCy’s lemmatiser only strips inflectional morphology

Stemming

removing what’s probably not a part of a word’s root/stem

import nltk
from nltk.stem.porter import *
stemmer = PorterStemmer()
for token in ['compute', 'computed', 'computing', 'computer', 'computers']:
    print(token + ' --> ' + stemmer.stem(token))
compute --> comput
computed --> comput
computing --> comput
computer --> comput
computers --> comput

We can see that the stemmer strips off both inflectional and derivational morphology off of computed, computer, computing, computers.

computing can be used in at least two ways; what caveat ought to be made, and what assumption does spaCy make?

Automatic inflection

adding inflectional morphology to ‘basic’ word forms

  • Verbal conjugation
  • Nominal inflection
from mlconjug3 import Conjugator
import warnings
warnings.filterwarnings('ignore')

conjugator = Conjugator('en')
verb = conjugator.conjugate("speak")

# Safely find the past tense key
past_tense_key = [k for k in verb.conjug_info['indicative'].keys() if 'past' in k.lower()][0]
form = verb.conjug_info['indicative'][past_tense_key]['1s']

print('speak + indicative past tense --> ' + form)
speak + indicative past tense --> spoke

Character-level models

A variety of tokenisation models that treat each character as a separate token.

Some models, e.g. Google’s byt5-base, appear to at least partially group characters together in a manner resembling linguistic units, i.e. morphemes.

Syntax and language technology

Sentence parsing

automatic syntactic analysis

classic NLP task

  • input: natural-language text
  • output: syntactic structure
    • constituency structure
    • dependency structure
    • constituency+dependency structure

stanza example

import stanza

# Download the English model (only needed once)
stanza.download('en', processors='tokenize,pos,constituency')

nlp = stanza.Pipeline(lang='en', processors='tokenize,pos,constituency')
doc = nlp('The time for action is now.')

# Access the constituency tree
tree = doc.sentences[0].constituency
print(tree)
(ROOT (S (NP (NP (DT The) (NN time)) (PP (IN for) (NP (NN action)))) (VP (VBZ is) (ADVP (RB now))) (. .)))

What is required for syntactic parsing?

  • a parser, obviously
  • syntactic treebanks
    • Penn Treebank

Do we actually need parsing?

  • sometimes we don’t
    • consider the ‘new’, LLM, approach, which requires no parsing
  • sometimes it can be quite handy

Language-specific perks and challenges

Same pipeline, different languages

We take one pipeline — tokenise → lemmatise → parse — and run it across a few typologically diverse languages.

  • English — the “easy” baseline: whitespace-delimited, light inflection
  • Russian — fusional, Cyrillic script, rich case/gender/number morphology, mature but still-improving lemma pipelines
  • Hebrew — non-concatenative morphology, right-to-left, optional diacritics

Other languages will present challenges of their own

  • Mandarin Chinese — no whitespace, compounding, no inflection
  • Korean — agglutinative: one space-delimited eojeol holds several morphemes

English

Runs the pre-loaded English pipeline over one sentence and returns (surface form, lemma, POS) per token. Note 's split off as its own token, children → child and were/being → be (suppletion and auxiliary collapse), and reorganized → reorganize (stemming would wrongly give organ).

import spacy
nlp = spacy.load("en_core_web_sm")
doc = nlp("The children's toys were being reorganized.")
[(t.text, t.lemma_, t.pos_) for t in doc]
[('The', 'the', 'DET'),
 ('children', 'child', 'NOUN'),
 ("'s", "'s", 'PART'),
 ('toys', 'toy', 'NOUN'),
 ('were', 'be', 'AUX'),
 ('being', 'be', 'AUX'),
 ('reorganized', 'reorganize', 'VERB'),
 ('.', '.', 'PUNCT')]

Perk. Trivial tokenisation; lemmatiser handles suppletion (children → child, were → be).

Mild challenge. Clitics ('s), hyphenation, and the stem-vs-lemma distinction. A stemmer reduces organize/organization to organ, losing meaning; the lemma preserves the lexeme.
